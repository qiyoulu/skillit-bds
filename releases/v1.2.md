# Skillit Kit BDS v1.2 — release notes
**Last updated:** 2026-10-08
**Status:** v1.2 source release. No Git tag or GitHub Release created.
**Comparison baseline:** `db5235b` — the v1.1 version bump. Covers every subsequent committed change and the current local work, not only the latest icon export.

## Summary
v1.2 expands the icon system, repairs generated tokens and component examples, clarifies brand and accessibility rules, improves source assets, and adds stronger verification tooling. The canonical palette, typography scale, spacing, radii, motion, and other token `$value` fields are unchanged from v1.1. Generated representations and guidance have been brought into line with those values.

**Migration required:** Icon filenames and some artwork changed. A frozen legacy directory provides a staged-migration source, but does not automatically restore old root paths. This is a minor brand-system release with explicitly documented consumer changes, not an unchanged-path SemVer compatibility promise.

## Icons and compatibility
- Expanded from **41 icon SVGs at the v1.1 bump to 90 canonical icons**. Growth includes earlier v1.1-era additions, the fresh re-export, revised drawings, and newly supplied assets—not just renames.
- Documented **29 previous-to-current ID mappings**, including later v1.1-era assets. This does not mean 29 icons from the original v1.1 baseline were renamed.
- Adopted appearance-based names and Heroicons vocabulary where the glyph corresponds. Semantic status props such as `success`, `error`, `warning`, and `info` remain independent of asset names. Skillit artwork remains authoritative; matching names do not redirect a Rails Heroicons helper.
- Added directional diagonals, briefcase, credit card, currency, inbox, map, handset variants, an enclosed-circle avatar, and the upward-arrow/square glyph. Preserved user-selected custom names such as `saw`, `concrete`, `pipe`, `user-hat`, and `user-round`.
- Distinguished three-node `share.svg` from `arrow-up-on-square.svg`.
- Normalized **78 single-color utility exports** to `currentColor`. Preserved **12 approved semantic/multicolor exports** and their opaque contrasting layers; geometry is verified against the supplied re-export.
- Updated artwork/rendering contracts for standalone and circular play/pause, checks, radio indicators, and switches. Circle media/status white glyphs are opaque paint, not transparent cutouts. Combined alpha masks flatten that contrast; validation/toast examples now use full background images. Inline per-layer styling is required for runtime recoloring.
- Added [`assets/icons/legacy/`](../assets/icons/legacy/README.md): **75 frozen prior-ID SVGs**, separate from the 90 canonical assets. It contains the 75 pre-v1.2-migration files; unpublished temporary export IDs are excluded. A manifest records migration targets, provenance, and SHA-256 hashes; validation rejects changed, missing, duplicate, or unlisted archive entries.

### Consumer migration
Use the [complete ID map](../components/icons.md#previous-ids--current-ids) and update copied SVGs, Figma names, image paths, CSS URLs, renderer IDs, and tests together.

Two reused names require artwork-aware migration:
- Previous `phone` is now `device-phone-mobile`; current `phone` is a newly supplied handset. The old drawing remains `legacy/phone.svg`.
- Previous `user-circle` is now `user-round`; current `user-circle` is a newly supplied enclosed-circle avatar. The old drawing remains `legacy/user-circle.svg`.

To remain on earlier artwork, consumers must explicitly select `legacy/` or point an old-version resolver at its copied directory. There are no automatic redirects or root-level aliases. Do not normalize or redraw archived SVGs. Archive removal requires a separately announced major-version migration; no removal date is set in v1.2. This BDS release does not deploy Rails, Squarespace, or workspace consumers.

## Generated tokens and typography
- Preserved all **92 canonical `$value` nodes** from the v1.1 baseline. Changes to token source descriptions/comments do not constitute new palette or type-scale values.
- Fixed decimal CSS custom-property escaping, missing/undefined references, duplicate/cyclic aliases, mobile clamp parity, and stale Tailwind size mappings.
- Corrected generated typography weights to the existing canonical tiers, including 650/550/450 rather than stale 600/500/400 representations.
- Repaired typography examples, leading/tracking, metadata treatment, quote tiers and attribution, and widow/orphan fallbacks that could harm responsive wrapping.
- Measured and documented Work Sans cap/x-height ratios of 0.66/0.50 and JetBrains Mono 0.73/0.55. Equal tier sizing is intentional, not an equal-x-height claim. Optical top alignment now uses the measured Work Sans cap height rather than the earlier 0.72 assumption.
- Clarified canonical rem spacing and paired button padding instead of a universal local-em rule; retained the approved compact 4px/8px exception.

## Color, feedback, and interaction
- Replaced the “one orange per section” quota with action priority: functional primary actions, selection controls, focus, and assigned data roles may repeat; maintain one dominant CTA.
- Kept Orange checkbox/radio/chip selection and focus, with Iron inner checks. Neutral utility icons and completed progress use Iron.
- Restored conventional semantic feedback: error red, warning yellow, success green, information blue. Noninteractive does not mean neutral.
- Removed the claim that outer shape encodes information type. Familiar glyphs, explicit labels, and semantic colors communicate status; control-versus-container geometry remains separate.
- Distinguished information “i” assets from help “?” assets.
- Standardized toast bodies as static 16px-corner Plaster panels with Iron messages/close controls and semantic icons—not matching semantic-colored pill backgrounds.
- Repaired native checkbox label/row activation, keyboard/state/submission behavior, separate chip indicator/check layers, select chevron positioning and focus, navigation sizing, and mobile/desktop modal positioning/transforms. Progress examples retain opaque Iron completed fill.

## Layout and accessibility
- Explicitly banned layout divider rules, heading rules, table gridlines, separator strokes, and all drop shadows. Use spacing, alignment, typography, and Canvas/Plaster contrast. Functional chart lines, control boundaries, link underlines, and keyboard-focus rings follow their own specifications.
- Clarified the equal-track 12-column grid, 24px gutters, 326px content-block minimum, canonical 1200px content width, and aligned header/body margins: 16px mobile, 32px tablet, shared centered desktop content.
- Corrected contrast checks and large-text point thresholds; clarified text resizing/reflow, modal focus containment/Escape/return focus, and native/forced-colors behavior.
- Preserved requested Orange focus at 2px with 2px offset without claiming it resolves contrast on every surface.

### Unresolved accessibility limits
These are documented limitations, not accessibility passes:
- Orange on Canvas: **2.6958:1**, below the 3:1 non-text/focus target; Orange on Plaster: **3.0177:1**, a narrow pass.
- Painter’s Tape on Canvas: **4.2312:1**, below 4.5:1 for normal text.
- Hard Hat on Plaster/Canvas: **1.8229:1 / 1.6285:1**, below 3:1 for essential graphical meaning. Labels do not improve these ratios; whether a graphic is genuinely redundant must be assessed in context.

## Email and data visualization
- Set **16px / Text-1x as the default and minimum for readable email text**, including signatures, contact information, addresses, copyright, legal links, captions, and references. Default Work Sans weight is 450 with 1.4 leading; 600 provides emphasis. The general 12px metadata exception does not apply to email.
- Allow contact rows to wrap rather than shrinking type. Corrected email padding and documented pixel fallbacks and Outlook/VML limitations without promising identical rendering across clients.
- Clarified that monochrome charts are a default, not an exclusive restriction. Approved categorical colors require labels/legends, non-color cues, and contrast checks; supply remains Painter’s Tape and demand Traffic Cone.
- Corrected chart label/reference opacity and typography, direct pie-label guidance, and neutral flowchart nodes. Data opacities encode marks, not reduced-opacity text.

## Logo, imagery, voice, and documentation
- Repaired Canvas source paint in mark, lockup, and favicon SVGs to the already canonical `#F7F1ED`, preserving geometry. Regenerated all nine approved PNGs at 512px height with their aspect ratios intact; mark exports are 448×512, not forced squares.
- Aligned logo clear space and raster-fallback guidance. Clarified neutral pattern use in empty zones, not beneath text or controls. CMYK remains provisional/unprofiled pending stock, profile, printer approval, and proofs.
- Clarified authentic imagery: real workers/product screenshots, no generative portraits or fabricated scenes; genuine photo grids and environmental aerials are permitted, not high-angle worker portraits.
- Maintained “Skillit Kit BDS” naming, sync/update metadata, restored truncated files, and repaired links, TOC anchors, examples, punctuation, and asset references. Removed the Procore reference document.
- Clarified canonical token authority, plain language, no overselling, network terminology, channel-specific craft-professional language, and Sam as a tool rather than a person.
- Corrected README integration guidance: Rails theme/config and onboarding CSS on `main`, copied artwork under `app/assets/images/bds/{icons,logo}/`, not `app/components/`. Documented stale consumer adoption and safe, scoped updates; removed unsupported automatic-compliance, universal-access, and MCP-service claims.
- Marked proposed website structure and unconfirmed product framing as proposals, not shipped inventory. Reusable metrics require approved sources, dates, cohorts, definitions, and owners; the disputed 72-hour starting event, worker-only “free” scope, and print approval gaps remain publication checks.

## Tooling and verification
- Expanded lint/validation to canonical scalar/composite parity, CSS syntax/escaping, variable references/cycles, Tailwind mappings, documentation declarations, geometry, contrast, and exact-path SVG paint exceptions.
- Added a standalone Ruby icon normalizer with dry-run/check/backup modes, targeted paint replacement, geometry preservation, idempotence, permissions preservation, and malformed-batch/backup-collision safeguards.
- Added browser/component/instruction regression suites with actual source assets, approved geometry fingerprints, layer/raster checks, native interaction tests, and failing controls. Python remains for specialist browser/image tooling rather than a blanket Ruby rewrite.
- Added reproducible logo export/check tooling with source/dimension validation, decoded RGBA pixel comparisons, actionable file errors, atomic writes, and permissions preservation. Raster parity is browser-build-dependent.
- Added legacy archive hash/inventory checks without relaxing current or external SVG paint checks.
